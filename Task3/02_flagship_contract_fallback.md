# №1. Выходной контракт и фолбэк

## Выходной контракт

На каждую помеченную операцию пакета сервис публикует одну запись в топик `operation-priorities`; её читает система ПОД/ФТ.

```json
{
  "schema_version": "1.0",
  "operation_id": "string",
  "batch_id": "uuid",
  "scored_at": "2026-10-14T09:15:00+03:00",
  "band": "URGENT | CONTROL_SAMPLE | RANKED",
  "priority_score": 87.5,
  "route": "MODEL | RULES_FALLBACK | FIXED",
  "reason_codes": ["NO_HISTORY"],
  "factors": [
    {"code": "TRANSIT_SHARE_7D", "text": "Доля поступлений за 7 дней, переведённых дальше в течение суток"}
  ],
  "source": {
    "model_version": "rank-anomaly-graph:1.4.0",
    "feature_set_version": "fs-2026.10",
    "feature_snapshot_at": "2026-10-14T05:00:00+03:00",
    "rules_version": "queue-rules:2.1"
  }
}
```

**Обязательные поля.** Обязательны все поля, кроме трёх условных:
- `priority_score` (перцентиль 0–100) — только для полосы `RANKED`;
- `factors` (до 5) — при `route = MODEL`; коды и тексты берутся только из справочника, без ПДн;
- `reason_codes` — при фолбэке, фиксированной полосе, нижней границе по правилу и пропуске данных.

`factors` — признаки, которые сильнее всего подняли оценку модели, с понятным описанием. По ним сотрудник видит, почему операция стоит высоко в очереди и что проверить в первую очередь. У каждой записи есть `factors` или `reason_codes`, поэтому сотрудник всегда видит причину приоритета. Внутри полосы C система ПОД/ФТ сортирует операции по `priority_score`.

**Ссылка на источник** — блок `source`. По нему и `operation_id` журнал аудита восстанавливает снимок признаков, версии модели и правил и сырую оценку — в течение срока хранения по 115-ФЗ.

**Проверки до публикации.** Пакет публикуется, только если:
1. каждая запись соответствует JSON-схеме;
2. на каждую входную операцию — ровно одна запись;
3. обязательные по ПВК и приостановленные операции стоят в полосе `URGENT`, а в полосе `CONTROL_SAMPLE` — ровно те операции, что отобраны до оценки;
4. `model_version` утверждена в реестре.

Пакет, не прошедший проверку, пересчитывается резервным скором. Если не проходит и он, ничего не публикуется, а операции остаются в очереди без приоритета, в порядке «по сумме».

**Нет данных.** Если устарели или пропущены признаки, нет истории клиента или сигнала KYC, приоритет считается по резервному скору или с индикатором пропуска, а причина пишется в `reason_codes` — см. коды `STALE_FEATURES`, `MISSING_FEATURES`, `NO_HISTORY`, `KYC_UNAVAILABLE` в таблице фолбэка. Событие, которое не удаётся разобрать, уходит в DLQ, а операция остаётся в очереди в порядке «по сумме».

## Фолбэк

Кейс всегда остаётся у человека. Фолбэк меняет только источник приоритета, а причина видна сотруднику в `reason_codes`. Пороги стартовые и уточняются в пилоте.

| Наблюдаемый признак (код) | Куда уходит кейс |
|---|---|
| Снимку признаков больше 36 ч или пусты критичные признаки (`STALE_FEATURES`, `MISSING_FEATURES`) | Резервный скор правил и KYC. При пропуске некритичного признака модель работает с индикатором пропуска |
| Значения за пределами обучающих данных: не меньше трёх критичных признаков вне [p0,5; p99,5] или новая категория ОКВЭД либо канала (`OUT_OF_RANGE`) | Резервный скор; оценка модели пишется только в журнал |
| История клиента короче 90 дней или сегмента нет в обучении (`NO_HISTORY`) | Резервный скор; отдельный стратум в контрольной выборке |
| Оценка на границе ёмкости K: перцентиль в пределах ±2 п. п. от линии, разница меньше точности модели (`ABSTAIN_ZONE`) | Решают правила: берётся большее из перцентилей модели и правил, поэтому операция может только подняться выше линии |
| Недоступны модель или БД признаков; ответ не прошёл проверку (`MODEL_UNAVAILABLE`, `CONTRACT_INVALID`) | Весь пакет — на резервный скор |
| Сигнала KYC нет больше 24 ч (`KYC_UNAVAILABLE`) | Модель работает с индикатором пропуска; алерт |
| Ночной расчёт не завершён к 07:00, лаг Kafka > 2 000 или пакет считается дольше 15 мин (`CAPACITY_LIMIT`) | Вчерашний порядок, новые операции — по резервному скору; алерт |
| Нет heartbeat сервиса больше 30 мин | Очередь «по сумме», как сейчас; алерт |
