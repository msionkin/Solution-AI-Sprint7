# Оценка 18 инициатив

| Инициатива бизнеса | Категория | Комментарий |
|---|---|---|
| 1. Автоматически выявлять подозрительные операции по счетам (транзит, обналичивание, дробление платежей под пороги). | Гибрид | Правила внутреннего контроля (ПВК), пороги и фиксация операций остаются детерминированными и не отключаются. Обучаемая закономерность нужна в одном звене: оценка риска операции для порядка разбора очереди (35 тыс. помечено, 10 тыс. разбирается). |
| 2. Распознавать и оцифровывать сканы документов, приложенных к кредитной заявке. | Гибрид | Распознавание текста (OCR) и определение типа документа — готовые модели; маршрутизация и хранение — обычный код. Самостоятельного бизнес-эффекта нет, это первое звено инициативы 18. |
| 3. Чат-бот, отвечающий клиенту, что входит в его тарифный план. | Обычная программа | Состав тарифа — факт из справочника тарифов и договора клиента, его достаточно найти и показать. *Вопрос бизнесу:* нужно ли отвечать на произвольные вопросы в свободной форме или достаточно показать условия тарифа в интернет-банке? |
| 4. Прогнозировать годовой уровень просрочки по портфелю кредитов МСБ. | Недостаточно информации | Формулировку можно понять двумя способами, и от этого зависит тип задачи. Если нужно одно число на год по всему портфелю, то за несколько лет истории набирается всего несколько таких чисел — модель на них не обучить, это расчёт или сценарный анализ. Если нужна вероятность невыплаты по каждому кредиту с последующим суммированием по портфелю — это ML-задача на истории выданных кредитов. *Вопрос бизнесу:* кто будет пользоваться прогнозом и что с ним сделает — сформирует резервы, заложит потери в бюджет или изменит лимиты кредитования по сегментам? |
| 5. Маршрутизировать входящие обращения по нужным отделам. | ML-кандидат | Классификация текста обращения; сигнал — отдел, который фактически закрыл обращение после переадресаций. |
| 6. Автоматически проводить платежи на сумму менее 30 000 ₽ без ручного контроля. | Заблокировано → уточнить | Порог — это правило, но снятие контроля по сумме противоречит обязанности выявлять операции по ПВК и создаёт ориентир для дробления. *Вопрос комплаенсу:* допустим ли упрощённый контроль для какого-либо класса операций; иначе задача сводится к приоритизации из инициативы 1. |
| 7. Дашборд с разбивкой обращений по регионам и продуктам. | Аналитика | Срез прошлого по уже размеченным полям, прогноз не нужен. |
| 8. Предсказывать, какие клиенты собираются уйти в другой банк. | Недостаточно информации | Сигнал в истории есть (закрытые счета, падение оборотов), но не определены ни «уход», ни действие по прогнозу. *Вопрос бизнесу:* что считается уходом (закрытие счёта или перевод оборотов) и что банк сделает с клиентом из списка? |
| 9. Голосовая аналитика звонков в кол-центр (тон, причины обращений). | Гибрид | Распознавание речи и классификация причин — модели; агрегация — аналитика. *Вопрос бизнесу:* результат нужен для отчётности или для действий по конкретному звонку? Основание на обработку записей — к ответственному за защиту персональных данных (DPO). |
| 10. Выявлять поддельные и отредактированные справки о доходах и бухгалтерскую отчётность. | Гибрид | Сверки с внешними источниками и оборотами по счёту — детерминированные; модель нужна для признаков редактирования документа и нетипичных соотношений показателей. |
| 11. Давать клиентам индивидуальные инвестиционные рекомендации по свободным остаткам. | Заблокировано → уточнить | Индивидуальная рекомендация — инвестконсультирование. *Вопрос юристам:* есть ли у банка этот статус; если нет — переформулировать в неиндивидуальное информирование о продуктах (см. 13). |
| 12. Полностью автоматически отказывать в кредите по скорингу, без участия сотрудника. | Заблокировано → уточнить | Решение исключительно на автоматизированной обработке персональных данных (ПДн) затрагивает права ИП и поручителей-физлиц и требует законного основания и порядка рассмотрения возражений. *Вопрос юристам:* применимо ли это к постановке; альтернатива — скоринг рекомендует, отказ подтверждает сотрудник. |
| 13. Рекомендовать клиенту подходящий продукт банка. | ML-кандидат | Закономерность «профиль клиента → подключённый продукт» выучивается по истории подключений. Согласие на маркетинговые коммуникации — к DPO. |
| 14. Сверять удержанные комиссии по эквайрингу с условиями договора и помечать расхождения. | Обычная программа | Расчёт комиссии по тарифу договора и сравнение с фактом. Если условия договоров есть только в PDF — их однократно заводят в справочник. |
| 15. Прогнозировать нагрузку на кол-центр для планирования смен. | ML-кандидат | Прогноз временного ряда; правильный ответ — фактическое число обращений, известное на следующий день. |
| 16. Генерировать PDF-договор на обслуживание из шаблона по данным клиента. | Обычная программа | Шаблонизация по данным из учётных систем. |
| 17. Блокчейн для хранения истории операций клиентов. | Обычная программа | Не относится к ML. Владелец данных один, распределённый реестр не нужен. *Вопрос бизнесу:* какую проблему решаем — защиту от изменения истории или обмен с внешними участниками? |
| 18. Извлекать финансовые показатели из неструктурированных бухгалтерских документов и банковских выписок. | Гибрид | Модель нужна для сканов, фото и разнородных форм; разбор структурированных выгрузок, арифметические проверки и расчёт коэффициентов — детерминированные. |
