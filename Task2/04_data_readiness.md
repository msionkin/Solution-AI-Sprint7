# Раздел 4. Готовность данных

| Поле | №1. Выявление подозрительных операций | №18. Извлечение финансовых показателей | №10. Выявление поддельных документов |
|---|---|---|---|
| Решение | Порядок разбора очереди финмониторинга. | Предзаполнение карточки финпоказателей для андеррайтера. | Флаг «требует проверки подлинности» до решения по заявке. |
| Объект и гранулярность | Операция по счёту (20–25 млн в месяц, из них 35 тыс. помечено), агрегаты по клиенту и сети контрагентов. | Документ пакета → страница → значение показателя. | Документ пакета; показатели из №18. |
| Источник и владелец | АБС и хранилище операций — ИТ; справочники тарифов и лимитов — операционный блок; сигналы правил и KYC-платформы, результаты разбора и расследований — финмониторинг (владелец меток). | Пакеты заявок в кредитном конвейере — кредитный блок; ручной ввод андеррайтеров — андеррайтинг. | Пакеты и показатели (№18); ГИР БО — ФНС (внешний источник); обороты по счетам — АБС; результаты проверок — служба безопасности и андеррайтинг. |
| Источник правильного ответа | Экспертная метка по гайдлайну — на разобранной очереди и на контрольной выборке, через дни. Исход расследования — через недели. Формально подтверждённые случаи — через месяцы, единицы. Три следа хранятся раздельно и не подменяют друг друга. | Эталонный ввод андеррайтеров со ссылкой на страницу или ячейку. Сейчас его нет: неизвестно, сохраняется ли ручной ввод структурно и с привязкой к документу. | Расхождение с ГИР БО и оборотами по счёту — автоматически, сразу, только для юрлиц и клиентов с оборотами в банке. Результаты проверок — недели. Подтверждённые подделки — единицы. |
| Доступность признаков в проде | Да: история операций, контрагенты, ОКВЭД, канал, назначение платежа известны на момент пометки. Графовые признаки пересчитываются пакетно, с задержкой не больше суток. Метки и исходы расследований в признаки не входят. | Да: признаки — сам документ. | Частично: ГИР БО — только по юрлицам и с задержкой публикации, у ИП на упрощёнке эталона нет; обороты есть, только если у клиента счёт в банке. |
| Разметка | Финмониторинг по единому гайдлайну (типология: транзит, обналичивание, дробление; ответ «эскалировать / нет / неясно»). 20% операций контрольной выборки (100 в месяц) независимо размечают два сотрудника, расхождения разбирает старший эксперт; согласованность между ними определяется по коэффициенту Cohen's kappa ≥ 0,61 (substantial agreement по шкале Landis & Koch, 1977). Если коэффициент ниже — правим гайдлайн, а не модель. | Андеррайтеры вводят эталон по гайдлайну (что считать значением, единицы, период). 20% пакетов независимо вводят два андеррайтера, расхождения разбирает старший андеррайтер. | Синтетические подделки делает команда проекта на реальных шаблонах. Реальные случаи размечают служба безопасности и андеррайтеры по единому протоколу проверки. |
| Смещение отбора | Сильное. Разбирались только операции, отобранные правилами и внешними сигналами, внутри них — в порядке суммы. Непроверенная операция ≠ чистая. Выводы по разобранной части не переносятся на 25 тыс. неразобранных в месяц. Закрываем постоянной вероятностной контрольной выборкой; размечать только очередь модели нельзя — это даст новое смещение, уже собственного производства. | Умеренное: в истории есть только заявки, дошедшие до андеррайтинга. Форматы последних лет могут не совпадать с текущими. | Сильное: проверялись документы, которые вызвали подозрение у андеррайтера. Подделки, прошедшие незамеченными, в истории числятся «чистыми». |
| Репрезентативность | Покрыты сегменты и регионы текущей клиентской базы. Не покрыты новые сегменты и новые типологии: эскалаций мало, подтверждений единицы. Стратификация контрольной выборки — по сегменту, сумме и типу правила. | Нужно покрыть: Excel и выгрузки бухсистем, текстовые PDF-выписки разных банков, сканы БО, фото с телефона, многостраничные таблицы, документы за несколько периодов, разные единицы (руб., тыс. руб.). | ИП на упрощёнке без эталона в ГИР БО; клиенты без счёта в банке; редкие отрасли с нетипичными соотношениями показателей. |
| Объём | Общий — миллионы операций за несколько лет. Важный класс: около 400 эскалаций в месяц, сильно смещённых. Контрольная выборка — 500 операций в месяц (≈ 1 500 за квартал). | Поток заявок неизвестен (уточнить). Эталонный набор: цель — не меньше 40 документов в самом редком формате. Размер в пакетах считается от доли этого формата. Предварительно — около 300 пакетов документов; уточняется выгрузкой распределения форматов из кредитного конвейера. <br>*Допущения:* около 20 ключевых полей в документе; при 40 документах × 20 полей = 800 значений. | Подтверждённых подделок — единицы. Синтетический набор — 300–500 документов. Расхождения с ГИР БО — по всей истории заявок юрлиц. |
| Качество | Назначение платежа — свободный текст с опечатками, сокращениями, ИНН и ФИО внутри. Контрагенты-юрлица и ИП идентифицируются по ИНН, но у одного контрагента бывают счета в разных банках — для графа узлы склеиваются по ИНН. У получателей-физлиц ИНН часто не указан (переводы по карте и СБП) — склейка только по счёту или карте, часть связей теряется. | Разнородные форматы, низкое качество фото, печати и подписи поверх цифр, единицы измерения не всегда указаны. | Метаданные файлов теряются при пересылке и конвертации; часть документов поступает в виде фото распечатки. |
| Право использовать | Банковская тайна. Решение о допустимости — за комплаенсом, ИБ и юристами. Ключевые вопросы по границам контура: <br>• *Внутри контура:* допустимо ли использовать историю операций для обучения модели в рамках ПВК? — комплаенс. <br>• *Выход в облако пилота* (псевдонимизированные признаки, ключ в банке, без сырого назначения платежа): остаются ли они банковской тайной, допустим ли провайдер как обработчик и какие требования к нему? — комплаенс, ИБ, юристы. <br>• *Вход сигнала KYC-платформы:* разрешает ли договор использовать его для обучения и хранить в истории? — юристы. <br>• *Факторы приоритета:* какие поля можно показывать в интерфейсах? — комплаенс. | Банковская тайна и ПДн представителей и поручителей. Решение — за DPO, комплаенсом и юристами. Ключевые вопросы по границам контура: <br>• *Выход в облако пилота:* подтвердить, что открытая БО из ГИР БО и синтетические документы не содержат ПДн и банковской тайны. — DPO, комплаенс. <br>• *Внутри контура:* допустимо ли использовать архивные пакеты для эталона и настройки модели (новая цель обработки) и сколько хранить эталон? — DPO, юристы. | Как у №18, плюс: <br>• *Вход данных ГИР БО:* условия использования API и данных ФНС. — юристы. <br>• *Флаг в карточке заявки:* какой порядок проверки и фиксации её результата нужен, чтобы отказ ИП или поручителю не считался решением только на основании автоматизированной обработки ПДн (152-ФЗ, ст. 16)? — юристы, кредитный блок. |
| Вердикт | **Разрыв с планом закрытия.** Данных и объёма достаточно. Экспертная оценка «подозрительно / нет» есть только по операциям, которые пометили правила и успели разобрать сотрудники, — в основном по крупным. Сколько подозрительных среди остальных операций, неизвестно. Узнать это можно только разбором случайной контрольной выборки, поэтому ограничивающий ресурс — время экспертов финмониторинга (около 120 ч в месяц). План: гайдлайн и контрольная выборка с первого месяца; пилот — ранжирование без обучения с учителем; обучаемый ранжировщик — когда накопятся метки (оценочно, через 6–9 месяцев). | **Разрыв с планом закрытия.** Метки фактически есть (ручной ввод), но нет эталона с привязкой к источнику. План: эталонный набор (предварительно около 300 пакетов) за 4–6 недель силами андеррайтеров; сохранение структурного ввода в кредитном конвейере. | **Разрыв с планом закрытия** для модельного звена: мало положительных примеров (редкий класс, а не смещённые метки, как в №1). План: синтетические подделки и расхождения с ГИР БО как прокси-метки. Детерминированные сверки — **готово**. |

Дефициты различаются: в №1 есть объём и признаки, но экспертная оценка есть только по разобранным, в основном крупным, операциям; в №18 метки есть, но не хватает их привязки к документу; в №10 мало самих положительных примеров.
